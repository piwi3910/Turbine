## Goal

Turn one-node Turbine into a real multi-node cluster: authenticated TCP transport, seed + peer-exchange membership with heartbeats, a cluster topology graph, cluster-wide request placement with forwarding and relayed streams, an owner-authoritative KV directory with an L3 fetch tier, and node failure handled as a scheduling event — proven by a deterministic in-process simulation on macOS and by lab scenarios on the two DGX Sparks.

## Architecture

New crate `turbine-transport` provides the `Transport` trait, a length-prefixed frame codec with the cap checked before allocation, a bounded `Connection` (data queue plus a one-frame priority slot for heartbeats) built over any byte stream, a Tokio TCP implementation and an in-memory `mem` implementation with link faults. `turbine-distributed` adds the versioned postcard `Message` protocol, the PSK HMAC handshake, a pure membership state machine, the cluster topology merge, placement scoring, and a `ClusterNode` runtime (links, heartbeats, peer lists, directory deltas, forwarding/relay, data-plane fetch, recovery) that reaches the engine only through the `LocalEngine` trait — which `turbine-server` implements and `sim::FakeEngine` fakes for `ClusterSim`. `turbine-kv` gains `directory::cluster` (the bounded `ClusterIndex` hint index, `decide_remote`, `compat_id`) and `tier::l3` (`L3ClusterTier`); `turbine-api` gains the cluster/topology/kv/status/debug routes and errors; `turbine-server` wires startup step 9 ("join cluster"), forwarding in its `InferenceBackend`, and the `fault-injection` endpoint.

## Constraints

From the spec (verbatim):

- Rust only; no Python (TS §21 rule 4). `turbine-transport` and all of Phase 6 are safe Rust (`unsafe_code = "forbid"` in `turbine-transport`; nothing is added to the phase-1 `unsafe_isolation` allowlist).
- New dependencies, each with its reason: `hmac` + `sha2` (PSK challenge-response), `crc32c` (block checksums; same algorithm Phase 7 uses), `rand` (nonces from the OS random source). `postcard` arrives in Phase 5.
- No fake distributed abstractions (TS §21 rule 5): every remote call has an explicit timeout, every message type an explicit failure outcome, and placement consumes the topology graph, never a flat node list.
- Every queue and cache is bounded (TS §21 rule 8): per-peer send queue (`distributed.transport.send_queue_frames`), forwarded requests per peer (`distributed.forwarding.max_inflight_per_peer`), in-flight KV bytes per node (`distributed.kv_fetch.max_inflight_bytes`), directory entries (`distributed.kv_directory.max_entries`), delta entries per frame (4,096), peers (_distributed.max_nodes_).
- Failure detection uses each node's local monotonic clock only; no cross-node clock agreement is assumed. Heartbeat `sent_at` is used only for RTT on the sender.
- KV blocks cross nodes only between compatible replicas: identical compatibility id = (phase-4 block identity fields: model fingerprint and version, KV format, block_tokens) + TP layout (tp size) — mismatches are never fetched (TS §8, §11).
- Every automatic decision (membership transition, routing target, forward, retrieve vs recompute, failure-handling step) carries a reason code and a metric (TS §14, §21 rule 7).
