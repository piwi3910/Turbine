# phase-2m-modularity — implementation plan

Status: draft
Spec: .procoder/specs/phase-2m-modularity.md

## Goal

Bring the code on main in line with Turbine's modularity rule — every model family, tool-call format, weight format, execution backend, card family, kernel implementation choice, logits processor and scheduling policy becomes one file (or directory) plus one entry in a static registry with a conformance suite — without changing any served output, configuration meaning or throughput, and merge the Phase 8 run-ahead registry work onto that layout.

## Architecture

`turbine-core` gains the shared registry convention (`turbine_core::registry::{Module, Registry}`: a static list of `&'static dyn Trait` with lookup by name, enumeration, a duplicate check and a `module_selected` log line) and open module names in the configuration (`ModuleName`, validated against the registries by the server before any port is bound). Each extension point then moves behind a trait and a registry inside the crate that owns it: `turbine-scheduler::policy`, `turbine-model::{sampling, weights, families, executor::decoder, formats}`, `turbine-kernels::{backends, cards}` and `turbine-device::discovery`; the kernel C ABI gains an optional v2.4 group through which the HIP library enumerates its implementations per op and runs the one the Rust `KernelRegistry` picks from the card profile's preference order. The Phase 8 run-ahead (`runahead/p8-umbrella`) is reshaped onto these registries, not merged verbatim.

Work is split into lanes that parallel agents build in separate git worktrees (`git worktree add ../Turbine-2m-<lane> phase-2m-modularity`); every task still lands alone on `phase-2m-modularity`, rebased onto the branch tip, and is measured on the lab before the next one lands. ## Constraints

From the spec (verbatim):

- No behaviour change for the models served today: greedy outputs, logprobs and tool/JSON outputs identical on the host test suites; served golden c1 strict and c16 batched pass for Llama and OLMoE; seeded sampling streams bit-identical (`crates/turbine-model/src/sampler.rs` seeded-stream tests, `tiny_server` seeded requests).
- No performance regression: `scripts/lab-bench.sh` on novanas GPU 0 per slice, Llama ≥ 747 tok/s and OLMoE ≥ 601 tok/s (97% of 770.4 / 619.8), TTFT p50 within 10% of 195 / 134 ms. Registry lookups happen at startup or once per shape, never per token.
- Engineering rules (AGENTS.md) stay binding: unsafe/FFI isolated in turbine-kernels (and turbine-device for discovery), no vendor GPU crate in the dependency tree, scheduler testable without GPUs, bounded queues, no micro-crates without an ownership boundary — modules live inside the existing crates (decision 2026-09-26).
- Kernel ABI: additive only, as a new optional minor group; a library without it still loads and the Rust side falls back to asking the library's default implementation (today's behaviour); `tests/abi_header_neutral.rs` keeps the header vendor-neutral.
- Configuration compatibility: every configuration file that loads on main today loads unchanged with the same meaning (`examples/turbine.yaml`, `scripts/lab/*.yaml`, test configs).
- Builds and tests run on novanas (`scripts/remote-cargo.sh`, `scripts/lab-test.sh`), never on the workstation; lab runs under the standing Phase 2 / 2c approval.
- Landing: one slice at a time on a branch, measured before the next lands (user feedback: land one change, then measure); parallel agents only for independent slices in separate worktrees.

From the interface contract and the repository (binding):

- Names in `.procoder/contract/interfaces.md` are used verbatim; this plan's additions are recorded there in §3.2 (configuration rows), §3.4 (the removed `ExecutionBackend` enum), §3.8 (`WeightFormatColumn`), §9.1 / §9.3 (ABI v2.4) and §24 (Phase 2m registries), committed with this plan. `TURBINE_ABI_VERSION` stays `2u` and `TURBINE_KERNELS_ABI_VERSION` stays `2`; `TURBINE_ABI_MINOR` becomes `4u`.

2. S-11 AC wants an unsupported support-matrix row to exit 2; the run-ahead branch exits 1 (`unsupported_row_exits_1_before_bind`) and AGENTS.md's exit 1 covers "model directory … unusable". Task 13 follows the spec (exit 2, before discovery and bind) and updates AGENTS.md.
3. The spec says "kernel selection per op already in status stays and gains the provider"; `/turbine/v1/status` on main has no kernel selections (they are only in the `kernel_selected` log and `turbine_kernel_provider_selected`). Task 1 adds `kernels` to the status document.
4. Edge case "`llama3_json` without `<|python_tag|>` refused at startup, as today": main does not refuse it (the tag id is optional; calls may open with `{`). Task 9 keeps main's behaviour: `<|python_tag|>` is an optional special token of `llama3_json`, and the refusal applies only to tokens a format marks required (none of the three formats has one).
5. `ModelFamily` "chat-template quirks" and `ToolFormat::render_tools`: neither main nor the run-ahead has family-specific template code or format-side tool rendering (tools are rendered by the model's template, and a template that renders no tools disables tool calling). The trait keeps `render_tools` with the default `None` for all three formats; no template-quirk hook is added.
6. Card profile "autotune seed": GEMM autotuning on main times candidates per shape at first use and has no seed or seed table; the profile carries no autotune field. `execution.gemm_autotune` keeps its meaning.
7. The C ABI requires the v2 entry points `turbine_<op>` to keep working, so a v2.4 library still needs a default for a caller that passes no implementation index (a v2.3-era caller). Task 11 makes that default the first implementation of the context's card-profile order that supports the descriptor (thresholds from `turbine_ctx_set_profile`); no threshold or architecture literal remains in the C++ selection path, but "the C++ library no longer chooses" holds only for callers that pass an index, which the Rust side always does from v2.4 on.
8. Spec names `SupportMatrix` and `Support`; the contract (§3.8) and the run-ahead use `SUPPORT_MATRIX`, `SupportStatus`, `SupportRow`, `resolve`. This plan keeps the contract names, and renames the matrix's `WeightFormat` column enum to `WeightFormatColumn` so it does not collide with the `turbine_model::weights::WeightFormat` trait.
9. `execution.backend: cuda` is refused on main by `Config::validate` with a message naming `phase-2b-nvidia`; with open backend names it is refused by the server's registry check (still exit 2 before bind) with `execution.backend: \`cuda\` is not registered (registered: cpu, hip)`.
