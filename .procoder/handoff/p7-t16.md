# Handoff: P7 Task 16 (HIP quantized experts and the quantized-MoE loader)

Branch `p7-t16` (from `p7-stack`). The builder stopped at its context budget with the kernel half done and the loader half not started.

## Done (commit "feat(kernels): quantized MoE experts on HIP ...", kernels half)

- `kernels/rocm/src/moe_quant.hip` (new, in CMake): per-expert static FP8 activation quantize, bias + gated activation (SwiGLU / gpt-oss clamp, separate or interleaved gate/up), down bias, shared-expert combine.
- `kernels/rocm/src/moe.cpp`: `MoePath::Quant`, impl `turbine_hip_moe_quant` (last entry of `kMoeExperts`, `NEEDS_HOST_OFFSETS`), `run_quant` = per-expert `turbine_qgemm` loop (always `prefill = 1`, so rows are batch invariant), `run_shared_expert`. `experts_supported` now: BF16 only in the plain pre-v2.16 form, quantized dtypes by configuration alone. The Rust shim probes `supports` with NULL pointers, so support cannot read pointers; operand checks (scales, `act_static_scale`, shared weights) are in `run_quant`. FP8 tensor experts without `act_static_scale` (W8A16) have no qgemm implementation and are refused at run time (`TURBINE_E_UNSUPPORTED`).
- `kernels/rocm/src/moe.hip`: `moe_route` takes `TURBINE_ROUTE_TOPK_THEN_SOFTMAX` and `router_bias` (bias added before the BF16 rounding; top-k on biased logits, then a softmax over the k).
- `crates/turbine-kernels/tests/hip_moe_quant.rs` (new): `fp8_block_experts_match_reference`, `fp8_tensor_experts_match_reference`, `mxfp4_experts_match_reference`, `quant_experts_batch_invariant`, `route_topk_then_softmax_with_bias_matches_reference`. Bound `|d| <= |want|/64 + rms/32` (the BF16 rounding of the dequantized weights in the kernels plus three chained GEMMs; the first run at `/128 + /64` had qwen3 1 token at ratio 1.63 and gpt-oss 1 token at 1.07, a BF16-noise outlier, not a bug).

Lab results (`scripts/lab-test.sh novanas -- -p turbine-kernels --test hip_moe_quant`, run 2 at the `/128 + /64` bound): fp8 tensor all cases pass (ratios 0.00 / 0.76 / 0.85 / 0.73), `quant_experts_batch_invariant` passes (0 differing elements at batch 1..63 vs 64 for fp8 block, fp8 tensor dynamic and static down, mxfp4), the route test passes. Run 3 at the loosened bound was queued behind the bench lock when this was written; see the final report of the builder for its result.
