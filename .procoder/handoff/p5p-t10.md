## What landed

1. **Scheduler (`crates/turbine-scheduler/src/scheduler.rs`)**: `Scheduler::extend(seq, tokens)`
   (states ≠ `Decoding` → `SchedError::NotDecoding`, added in `request.rs`; `tokens` 0 = no-op)
   stores `SeqEntry.extend_pending`. `plan()` plans extensions **before** `plan_decodes` (the
   item replaces the sequence's decode; `plan_decodes` takes the candidate list and skips
   extended sequences, and re-checks the state after the preemption loop — preemption inside the
   plan must drop the decode of its victim). The item is `BatchKind::Prefill { start, len }`
   with `len = 1 + tokens`, taken from the token budget left after the decodes (the throttle
   fraction applies) and planned before the prefill chunks. Not coverable — budget, the
   executor's logits-row capacity, or the pool — it is **dropped** and the sequence decodes;
   a request whose plan is in flight defers its extension. `preempt` / `finish_seq` /
   `remove_request` clear the pending extension. `IterationOutcome.rolled_back: Vec<(SeqId,
u32)>` shortens the table through the new `shorten_table` (shared with `shrink_plan`) and
   frees blocks left empty; `apply_samples` handles it too (outcome without a plan).
   Engine invariant: `appended + rolled_back = len` per extension item keeps
   `table.tokens = prompt + generated − 1` (the engine commits the disagreement token and the
   next step re-feeds it — see Task 12).
2. **Row capacity**: an iteration's total logits rows stay ≤ `max_running_requests` (the
   executor's head buffers are sized `max_seqs` rows = `max_running_requests`; the pack refuses
   more, `InvalidArgument` "logits rows exceed max_seqs"). The scheduler keeps its plans inside
   the same bound via a `rows` counter (`plan_extensions` and `schedule_chunk`), so extensions
   shrink what prefill chunks may take in that iteration. Callers bound `tokens` by
   `structured_output.jump_forward_max_tokens` (Task 12); the plan also caps by the policy's
   chunk cap and `prompt_len + max_new_tokens`.
3. **Executor (`crates/turbine-model/src/executor/`)**: `SeqSlice.logits_rows: u32`
   (1 ≤ rows ≤ `q_len`, validated in `check_seq`; > 1 never device-reduced — `reduce: Some`
   with rows > 1 is refused; every existing caller sets 1). `Logits` slots are `Full { row,
rows }` blocks: `slot(i)` is the **last** row (the sampled one), `full_row_index(i)` the
   first, and the new `Logits::rows_of(i)` returns all rows row-major in position order
   (panics on a reduced sequence). `Logits::mixed_rows` builds them (`mixed` is the 1-row
   case). The decoder's final norm gathers one source row per destination row
   (`norm_runs(row_src)`; reduced sequences first, a multi-row sequence's rows consecutive) and
   the LM head runs `Σ logits_rows` rows through the same `[max_seqs]`-row buffers. The TP
   leader's `tp_lm_head` and all-gather see the row total. The prefill-overlap split forces
   `logits_rows: 1` on both halves' slices (their logits are never gathered). `PendingRead`
   carries per-sequence `(is_reduced, rows)`; feeds (`last_tokens`) stay per sequence.
4. **Simulator**: `Simulation::with_extensions(every, max_k)` — deterministic (no RNG): every
   `every`-th iteration extends the first decoding sequence by `1 + next % max_k`, always fully
   accepted. `poisson_run` (feeding `decode_never_starved` and `chunk_budget_runs`) uses
   `(7, 3)`. `execute` handles extension items (`appended = len`; the context check becomes
   `prompt + generated − 1 + len`), `check` exempts them from the not-decoded invariant.
   Digests re-recorded: `decode_never_starved` → 10772755057896660484,
   `chunk_budget_respected` → 15676167015522452859; **every other workload's plan digest is
   unchanged** (documented in `sim/digests.rs`).
5. **Tests**: `scheduler::tests::extend_and_roll_back` (the spec's five scenarios) and
   `tiny_model multi_row_logits_match_single_steps` (both tiny checkpoints, CPU provider, 8
   rows vs 8 single steps within 1e-4, reduced decode unchanged beside it, `logits_rows` 0 /
   > `q_len` / total > `max_seqs` refused). Mutation-checked ×4 (all red, restored): the
   > extension budget check dropped; `rolled_back` ignored in `complete`; `logits_rows` clamped
   > to 1 in the head's plan; the multi-row final-norm sources not advanced per row.
