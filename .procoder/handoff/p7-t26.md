## Fix 2 — the harmony tool grammar never matched the real model (compile-level fix landed;

### served `required` still fails later — OPEN, see below)

`lab_openai harmony_channels` failed at `tool_choice: "required"` with llguidance
`ParserTooComplex` on the first token. Root cause: the harmony markers (<|channel|>,
<|constrain|>, <|message|>, <|call|>) are special added tokens of the gpt-oss tokenizer, and
llguidance's trie carries them with the special-token marker — a quoted literal in the grammar
is plain text and can never match them. `call_rules` now emits `<|...|>`-shaped runs as bare
lark atoms (`envelope::lark_envelope`, `envelope::is_marker_atom`), the harmony call anchors at
`<|channel|>` (the generation prompt ends with `<|start|>assistant`; `CALL_OPENER_SHORT` was
already documented), `sample_call`/`HARMONY_ONE`/`HARMONY_TIME` take the generation form, and
the conformance suite + `enveloped_conformance` add each format's marker atoms to the fixture
tokenizer before building its compiler (`Tokenizer::add_special_tokens`, the wrapper gained
Clone). The plain/streaming channels work served; on the real tokenizer the grammar compiles
and the model writes the envelope perfectly.

OPEN — the served `required` call now fails a few tokens later with "the constraint allows no
token" (step_mask's empty mask) at generated 17 tokens: the model wrote
`<|channel|>commentary to=functions.get_weather <|constrain|>json<|message|>` + ~5 JSON tokens,
then the next mask was empty. A standalone walk of the grammar on the real tokenizer
(`turbine-model/tests/gpt_oss_grammar_probe.rs`, `--ignored`, novanas paths) never dead-ends —
forced runs and masks carry it through a complete call — so the grammar is sound and the
failure lives in the engine's constrained-sampling path (overlap scheduling + jump-forward
interaction, or the x-guidance whitespace policy: `json_options()` demands
`whitespace_pattern {1,16}` with `whitespace_flexible: false` while the model naturally writes
`": "` with a space the compact schema forbids). The step error now names the choice and its
generated tokens (kept — a genuine message improvement). Next builder: extend the probe to
mirror the engine's overlap/jump-forward flow, or disable `structured_output.jump_forward` /
overlap for a discriminating serve; check whether the mask goes empty after the model's own
`": "` token diverges from the compact JSON.
