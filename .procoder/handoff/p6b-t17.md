## The open item that blocks the GPU legs

**The executor's pool view cannot address per-class pages.** `BlockPool::view` reports
`num_blocks = base_blocks` with flat base-class addressing, and the attention/append kernels
compute a block's address from the block id against one `kv_layer` stride — a block sitting
in a class slab (any id ≥ base) is refused ("block id N is outside the pool of M blocks").
So with page classes present, serving fails at the first forward — found by the tiny-server
cpu tests (`tq_kv_serves_on_cpu`). Consequences, as committed:

1. `kv.recent_window_blocks` defaults to **0** (spec amended accordingly: "1 intended, 0
   until the addressing exists"). The window's hierarchy/scheduler/simulator paths are in
   and tested; nothing serves with it on.
2. The ladder's L0 step stays dead on a serving path (as before this task): the pool only
   grows classes when the window is on or `kv.ladder.l0` is enabled with the ladder — and
   `kv.ladder.l0` was already refused at startup (Task 16). I did not change that refusal.
3. **The golden c1 window check (my step 4) and the multi-turn A/B (step 5) did not run** —
   with the window defaulting off and the L0 ladder refused, neither candidate is servable.
   `scripts/lab-test.sh novanas --tier quick` is running as this is written (launch
   ~19:50); expect green (the GPU surface is dormant without classes).

Options for the follow-up task:

- **A (recommended)**: give the executor per-class addressing — pass the pool's
  `block_segments` (or a per-class `kv_layer` pointer table) through the ABI and have the
  mixed attention/append resolve a block's page by its class; the view reports every page id.
  Then flip the window default to 1, run the golden c1/c16 re-check of S-5 and the Task 17
  A/B, and revisit `kv.ladder.l0`'s startup refusal.
- **B**: keep L0 class pages out of the executor's pool entirely — the L0 ladder rewrites
  live in a side pool; promotions decode back into flat base pages. Cheaper but caps the
  capacity win (the compressed blocks must fit beside the flat pool).
- **C**: drop the window's separate class and run the window over the _fp8_ rung instead
  (a class page smaller than a bf16 base page fits today's machinery) — but that changes
  the user decision (BF16 window over tq4) and only helps bf16-base pools.
