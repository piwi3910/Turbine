## Blockers (why the plan as written cannot be built)

1. **Attention output gate has no op.** `attn_output * sigmoid(gate)` needs a multiply by a
   sigmoid of a per-token, per-head value. The ABI exposes only `ADD` (`a+b`) and `SILU_MUL`
   (`silu(a)*b`); neither yields `sigmoid(g)*attn` (no exp, no divide, no mul). Folding it into
   the o_proj GEMM is not possible (the gate is elementwise on the attention output, not a row
   scaling of the weight). This needs a new op (e.g. `TURBINE_OP_SIGMOID_MUL`) or a gate field in
   the attention descriptor — a kernel/ABI addition Task 31 does not list.

2. **Q projection is per-head interleaved and the ABI has no head stride.** `q_proj` gives
   `[tokens, heads, 2*head_dim]` with query/gate per head; the decoder's q slice is
   `part(0, &[heads, head_dim])` over a contiguous `[tokens, heads*head_dim]` buffer. A
   *load-time row reorder* is feasible with the loader's existing `WeightSlot`/`SlotSource`
   (declare each head's query and gate rows as separate `axis: 0` row-range slots into a
   reordered `[q_all | gate_all | k | v]` stack — `plan` indexes a name once but plans every
   slot, and `StackPlace.offset` gives the order), plus a 4-group `Split`. This is not the
   `ATTENTION_OUTPUT_GATE` hook shape the plan describes and still leaves blocker 1.

3. **The linear-attention layer does not fit `DecoderExecutor`'s `Layer`.** `Layer` always holds
   `w_qkv`/`wo`; `build`, `attention_part`, `Split`, `fuses_norm_residual` and the fused-decode
   path all assume n≥1 KV heads and a QKV projection. A linear layer (`in_proj_*`, conv1d,
   A_log, dt_bias, gated RMSNorm, out_proj, no KV) needs a token-mixer branch, `fuses_norm_residual`
   forced off for hybrids, and a private per-sequence state map (recurrent F32
   `[v_heads, v_dim, k_dim]` + conv ring `[conv_dim, k-1]`). That last item is the `StateSlots`
   Task 32 replaces.

4. **`ModelArchConfig.state` / `layer_kinds` plumbing.** `FamilyConfig`/`ModelArchConfig` have no
   GDN dims; `families::tests::layer_kinds_and_state_layout`'s `expected_kinds_and_state` must
   learn the linear state bytes (comment already anticipates it). `config.rs`'s `parse_config`
   path also needs the `qwen3_5_text` rope layout (`rope_parameters` is already understood).

5. **The `naive` decoder must implement the same math** (`testing/naive.rs`), or
   `conformance::families` (`crates/turbine-model/src/conformance/families.rs`) fails on the
   first `load`/`naive` check — so a partial registration is not committable; the whole path
   (executor + naive + tiny writer) must land together.

## Answer to the S-18 tool-format question (hermes vs qwen3_xml)

`hermes` cannot parse the Qwen3.5 template's call. `tokenizer_config.json`'s template emits
`<tool_call>\n<function=NAME>\n<parameter=k>\nv\n</parameter>\n</function>\n</tool_call>`
(`tokenizer_config.json`, the `tools`/`tool_calls` branches); `hermes` (`formats/hermes.rs:161`)
expects `{"name": …, "arguments": {…}}` between the tags and returns `ToolParse::Content`
otherwise. So S-18 needs a new **`qwen3_xml`** format (`formats/qwen3_xml.rs`): an XML grammar
`<tool_call><function=NAME><parameter=k>…</parameter>…</function></tool_call>` (parameter values
free text up to `</parameter>`, mapping/sequence values JSON-encoded as the template does),
registered in `formats/mod.rs` with `registry_conformance`. The template also wraps reasoning in
` thinking…</think>`, so the existing `qwen_think` reasoning parser applies.

### The remaining atomic landing, concretely

The family cannot be registered until `conformance::families` passes, which needs all of:

1. **`DecoderExecutor` token-mixer branch.** `Layer`'s `w_qkv`/`wo` are unconditional; make the
   mixer an enum (`Attention { w_qkv, wo, attention: HookWeights, gated: bool }` |
   `Gdn(GdnLayer)`), branch in `build` on `cfg.layer_kinds[i]`. Full layers of a gated family
   use a fourth `Split<4>` (`[q_dim, q_dim, kv_dim, kv_dim]`, `fused: false`, so the per-head
   Q/K norm can read dense q/k) over the `q_gate_kv_proj_name_at` stack; the output gate is
   `TURBINE_OP_SIGMOID_MUL` on the attention output (`[t, q_dim]` = `[t, heads·head_dim]`) with
   the gate part, before `wo`. `fuses_norm_residual` already returns false when
   `self.qkv.fused` is false (`QK_NORM_PER_HEAD::fuses_qkv` is false), so the fused-decode path
   is naturally off; `layers_overlapped` (TP) is irrelevant — Qwen3.5 is one-device
   (`tp_decoder_spec None`) until Task 34.
2. **GDN layer.** `GdnLayer { in_qkv [conv_dim,hidden], in_z [value_dim,hidden],
   in_a/in_b [v_heads,hidden], conv_w [conv_dim,1,4], norm [v_dim], a_log/dt_bias [v_heads],
   out_proj [hidden,value_dim] }`. Per forward: `in_proj_qkv` GEMM → `CONV1D` (channels
   `conv_dim`, `activation: 1`, per-sequence conv state `[slots, conv_dim, 3]`) → split
   q|k|v → `in_proj_z/a/b` → `GDN` (prefill `cu_seqlens`, decode one token/seq; per-sequence
   state `[slots, v_heads, v_dim, k_dim]` F32) → gated RMSNorm (`RMSNORM` over
   `[tokens·v_heads, v_dim]` with `norm [v_dim]`, then `SILU_MUL` with `z`) → `out_proj`.
   Buffers: `gdn_qkv`, `gdn_conv`, `gdn_z`, `gdn_a/b`, `gdn_g/beta` (F32), `gdn_scan`,
   `gdn_state`, `gdn_conv_state`, `gdn_slots` (I32 `[seqs]`); add their bytes to
   `workspace_of`. **State slots**: a private `HashMap<SeqId, i32>` + free list on the executor
   (Task 32's `StateSlots` replaces it); resolve in `forward` (`&mut self`) before `launch`,
   allocating a slot per new `SeqId` and zeroing it when the sequence starts fresh
   (`cached == 0`), so the conformance "ragged" re-prefill and "chunked" carry both hold.
   `requirements_of` must add the GDN/conv ops and the wider gated GEMM.
3. **`g` and `beta` — a real gap the earlier analysis missed.** `GdnContext` takes `g` and
   `beta` already computed; `beta = sigmoid(in_proj_b)` and
   `g = -exp(A_log) · softplus(in_proj_a + dt_bias)`. The ABI has **no** sigmoid/exp/softplus
   op (unlike the output gate, this was not in the 2026-10-16 decision). Two honest options,
   both fine for a first landing but a **design question to report, not decide alone**:
   (a) compute `g`/`beta` on the host from the small `[tokens, v_heads]` BF16 `a`/`b` tensors
   (a readback + F32 upload per GDN layer per step — correct on CPU and HIP, slow on HIP); or
   (b) add a small ABI op (e.g. `TURBINE_OP_*` for `softplus`/`exp`) or fold the `a`/`b`/`A_log`/
   `dt_bias` inputs into the GDN descriptor — a new kernel-ABI decision, out of scope here.
4. **`(1 + w)` RMSNorm.** `Qwen3_5RMSNorm` is `output · (1 + weight)` for `input_layernorm`,
   `post_attention_layernorm`, `q_norm`, `k_norm`, `model.norm`. No norm flag in the ABI, so
   add 1 to those weights at load time (backend-agnostic: read the `[dim]` weight back, add 1.0
   in F32, re-upload — load-time only). The GDN's gated norm is plain `weight · rms(x) · silu(z)`
   and must **not** get the offset. The `naive` decoder must apply `(1 + w)` directly.
5. **`naive` decoder** (`testing/naive.rs`): a `cfg.gdn.is_some()` GDN branch (conv, recurrence,
