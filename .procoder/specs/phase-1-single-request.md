# phase-1-single-request

Status: complete

Source: `turbine-spec.md` §19 Phase 1 (single-request correctness), with §3, §6, §7, §13, §16, §17 and §21. Sections of that document are cited as "TS §N". Builds on `.procoder/specs/phase-0-skeleton.md` (config model, observability, device discovery, API shell, `turbine-bench`, `scripts/lab-test.sh`). Decisions are recorded in `.procoder/ask/decisions.md` ("Answers log for phase 1–8 spec questions (2026-09-25)"), which this spec follows where it differs from TS.

Amendments to TS made by those decisions:

- Amends TS §3 ("Qwen-family decoder model first", "prioritize current Qwen MoE"): the Phase 1 target is the dense BF16 `meta-llama/Llama-3.2-3B-Instruct`; the Qwen families (dense, MoE, Qwen3.5/3.6 hybrid Gated DeltaNet) move to the Phase 8 model-families track.
- Amends TS §19 Phase 1 ("Qwen BF16, CUDA/kernel bridge") and Phase 8 ("AMD/ROCm … as separately scoped work"): Phase 1 executes on AMD — one Radeon AI PRO R9700 (`gfx1201`) in novanas through a HIP kernel library. NVIDIA/GB10 execution follows right after Phase 2 in the proposed follow-on spec `phase-2b-nvidia`, behind the same vendor-neutral kernel traits and C ABI.
- Amends TS §6 (provider candidates FlashInfer / CUTLASS / cuBLASLt): on AMD the providers are hipBLASLt (GEMM) and Composable Kernel ck_tile FMHA (attention); the NVIDIA providers of TS §6 arrive with `libturbine_cuda.so` in `phase-2b-nvidia`.

## Problem

After Phase 0, Turbine starts, validates its configuration, discovers GPUs and answers every inference route with 503: it cannot load a model, tokenize text or run a forward pass. Nothing later in the roadmap — batching, paged KV, pressure control, KV tiers — is worth building on a forward pass whose numerics have not been proven against a reference, because every later optimisation must be checked against a known-correct path (TS §21 rule 1). Phase 1 is the smallest correct vertical slice: read `meta-llama/Llama-3.2-3B-Instruct` (BF16, 28 decoder layers, hidden 3072, 24 query heads and 8 KV heads of dimension 128 — grouped-query attention — SwiGLU MLP of width 8192, vocabulary 128256, Llama-3 scaled rotary embedding, tied input/output embeddings) from safetensors, tokenize it with its _tokenizer.json_, execute it on one R9700 through external kernel providers (hipBLASLt, Composable Kernel) behind a thin vendor-neutral C ABI in a prebuilt `libturbine_hip.so`, generate tokens for one request at a time with SSE streaming, and prove tokens and logprobs match a Hugging Face transformers BF16 reference within a stated tolerance. The 6.4 GB of BF16 weights fit one 32 GB card with room for a full-context KV cache, so the phase tests the execution path, not memory tricks.

## Users

- **Turbine developers (humans and AI agents):** need a model/kernel boundary they can test on macOS without a GPU (CPU reference provider, tiny synthetic checkpoint), per-kernel correctness tests on the R9700 in novanas, and one command that compares Turbine's tokens and logprobs with the committed reference.
- **Operators evaluating Turbine:** need `turbine-server --config <file>` to load the model, report readiness only when it can serve, refuse to start (before loading gigabytes) when the model, tokenizer, kernel library or memory budget is wrong, and answer `/v1/completions` and `/v1/chat/completions` with streaming for one request at a time.
- **Benchmark runners:** need Turbine to accept the requests `turbine-bench` sends (`stream`, _stream_options.include_usage_, `ignore_eos`) so single-request TTFT and ITL are recorded as a baseline (TS §18).

## In scope

- [S-1] New crates, each with Phase 1 content: `crates/turbine-tensor` (dtypes, shapes/strides, the `Tensor` struct of TS §6, a safe `DeviceBuffer` handle), `crates/turbine-kernels` (capability traits, kernel registry, CPU reference provider, runtime-loaded shim bindings), `crates/turbine-model` (model config, safetensors loader, tokenizer and chat template, Llama executor, generation loop). The vendor-neutral C ABI header `kernels/include/turbine_kernels.h` and the HIP shim project `kernels/rocm/` (CMake + `hipcc`, producing _libturbine_hip.so_; TS §5 names the directory). `unsafe_code = "forbid"` stays in every crate except `turbine-device` and `turbine-kernels`.
- [S-2] Safetensors loader: reads the checkpoint's index (`model.safetensors.index.json`) or single _model.safetensors_, validates every header (size bound, dtype, shape × dtype size = byte range, ranges inside the file and non-overlapping), maps checkpoint tensor names (`model.embed_tokens.weight`, `model.layers.<i>.{input_layernorm,self_attn.{q,k,v,o}_proj,post_attention_layernorm,mlp.{gate,up,down}_proj}.weight`, `model.norm.weight`, optional _lm_head.weight_) to the executor's parameter slots, reports unexpected tensors by name and refuses to start on a missing one, and uploads weights to the device through positioned reads into a bounded staging buffer (no `mmap`, so `turbine-model` stays free of `unsafe`). Pickle formats (`*.bin`, `*.pt`, `*.pth`, `*.ckpt`) are never opened (TS §16).
- [S-3] Model config parsing from _config.json_ and _generation_config.json_: architecture, layer count, hidden size, head counts, head_dim (explicit or hidden / heads), intermediate size, _rms_norm_eps_, _rope_theta_ and _rope_scaling_ (`rope_type: llama3` with factor, low/high frequency factors and original max positions), _tie_word_embeddings_, vocabulary size, _max_position_embeddings_, EOS ids. An allowlist: architecture `LlamaForCausalLM`, every weight tensor BF16, no _quantization_config_; anything else stops startup with the offending field named and the supported set listed.
- [S-4] Tokenizer and chat template: Hugging Face _tokenizer.json_ via the `tokenizers` crate; the model's chat template (_chat_template.jinja_, else _chat_template_ in _tokenizer_config.json_ — Llama-3.2 ships the latter) rendered with `minijinja` plus the Python-compatibility methods the template uses (`minijinja-contrib` pycompat: `.strip()`, `tojson(indent=…)`) and the host functions it calls (`raise_exception`, `strftime_now` evaluated in UTC); `chat_template_kwargs` (e.g. `date_string`) passed through; special tokens and EOS ids from _generation_config.json_ and _tokenizer_config.json_; incremental detokenization that never emits a partial UTF-8 sequence.
- [S-5] Tensor and memory layer: `DType` (BF16, FP16, FP32, INT32, INT64), `Tensor` per TS §6, `DeviceBuffer` owning one device allocation freed on `Drop`, and a startup memory budget (weights + KV reservation for _model.max_seq_len_ tokens + workspace + _reliability.emergency_vram_reserve_ ≤ available device memory) checked before any weight is read. Available memory is the device's free memory from `turbine_mem_info` on `dedicated` devices (the R9700) and the minimum of that and host `MemAvailable` on `unified` devices (vendor-neutral logic, first exercised on GB10 in `phase-2b-nvidia`).
- [S-6] Kernel registry: capability traits for GEMM, attention (prefill and decode), normalization, rotary embedding, activation, embedding gather and elementwise add, each `supports(cfg) -> bool` + `execute(ctx) -> Result<()>` (TS §6). The registry picks, per op and config, the first provider in a configured order that supports it, logs each selection with its reason, and fails startup naming the op and config when no provider supports it. Two providers: `cpu-reference` (pure Rust, f32 accumulation, always available) and `hip` (the shim below). The traits and descriptors carry no vendor types, so the `cuda` provider of `phase-2b-nvidia` implements the same ones.
- [S-7] HIP shim _libturbine_hip.so_: implements the C ABI (`turbine_abi_version()`, build-architecture report, device context and stream management, allocation and copies, one entry point per op). GEMM through hipBLASLt; prefill and decode attention (causal, GQA, head_dim 128, BF16) through Composable Kernel ck_tile FMHA; RMSNorm through ck_tile `rmsnorm2d` where it has a `gfx1201` instance. Embedding gather, Llama-3 rotary embedding, SiLU-and-multiply and residual add — which no ROCm library ships as standalone kernels — are minimal Turbine HIP kernels in `kernels/rocm/src/`; so is any op whose configuration the chosen library cannot run at all on `gfx1201`, recorded in the selection log. Performance-motivated custom HIP kernels replacing a library kernel are written only after profiling shows the gap (TS §21 rule 3). Built by CMake with `hipcc --offload-arch=gfx1201` against ROCm 7.14.1, then loaded at runtime with `libloading`, so the Rust workspace still builds and tests on macOS with no ROCm installed.
- [S-8] Llama executor: the forward pass for one sequence — token embedding, per layer (RMSNorm → Q/K/V projections → Llama-3 scaled RoPE on Q and K → causal GQA attention → output projection → residual add → RMSNorm → gate/up projections → SiLU-and-multiply → down projection → residual add), final RMSNorm and LM head (the embedding matrix when _tie_word_embeddings_ is true) producing FP32 logits — with a contiguous per-request KV cache of [layers, 2, _model.max_seq_len_, kv_heads, head_dim] BF16 (paged KV is Phase 2).
- [S-9] Generation loop: prefill, decode, sampling on the host from FP32 logits (greedy when `temperature` = 0, otherwise temperature, `top_k`, `top_p`, seeded PRNG), stop on EOS ids, stop strings, `max_tokens` or _model.max_seq_len_, and cancellation checked between decode steps.
- [S-10] Inference API for one request at a time: `POST /v1/completions` and `POST /v1/chat/completions`, streaming (SSE) and non-streaming, `GET /v1/models` listing the served model, `/ready` reflecting load state. A second request while one is generating is rejected with 429. A client disconnect cancels generation and frees the slot.
- [S-11] Golden-output tooling: a reference generator `scripts/golden/hf_reference.py` (Python, PEP 723 inline dependencies with exact pins of `torch` and `transformers`, run with `uv run`; fixture-generation time only, never in the build or serving path) that runs the committed prompt set through `AutoModelForCausalLM` in BF16 with greedy decoding and writes JSONL fixtures; a `turbine-golden` binary (in `benches/turbine-bench`) that compares an OpenAI-compatible endpoint against those fixtures and can also capture fixtures from any OpenAI-compatible endpoint (for recording other engines); committed prompts, reference and tolerance under `tests/golden/`; an in-process GPU test that compares logprobs directly against the same fixtures.
- [S-12] Tiny synthetic checkpoint generator (test utility in `turbine-model`) producing a random-weight `LlamaForCausalLM` checkpoint (2 layers, GQA with 4 query and 2 KV heads, small vocabulary, tied embeddings, llama3 rope scaling) and a matching tokenizer, so the loader, executor and API are tested end to end on macOS through the CPU reference provider.
- [S-13] Lab execution on novanas: `scripts/lab-test.sh novanas` builds _libturbine_hip.so_ and runs the GPU-gated tests on the R9700s with the weights mounted read-only; `scripts/lab-serve.sh novanas <config>` runs `turbine-server` there for manual golden and benchmark runs. Weights are provisioned under `/home/piwi/turbine-models/<slug>`; tests read `TURBINE_TEST_MODEL_DIR` and never download.
- [S-14] Phase 1 metrics and structured logs for model load, kernel selection and per-request latency (see Interfaces).

## Out of scope

- Concurrent requests, continuous batching, prefill/decode queues, chunked prefill, paged KV, request timeouts (Phase 2).
- Mixture-of-experts execution; `allenai/OLMoE-1B-7B-0125-Instruct` joins in Phase 2.
- NVIDIA/CUDA execution (`libturbine_cuda.so`, FlashInfer / CUTLASS / cuBLASLt per TS §6, GB10 unified memory): follows right after Phase 2 in the follow-on spec `phase-2b-nvidia` proposed in `phase-2-serving-runtime`. Phase 1 keeps the traits and C ABI vendor-neutral and adds no CUDA code; Phase 0 NVIDIA discovery is unchanged.
- Memory pools/reservations beyond the startup budget check, pressure states, predictive admission, recovery (Phase 3).
- Prefix sharing, CPU/NVMe KV tiers (Phase 4). Multi-GPU (Phase 5, on the novanas R9700 pair) and multi-node (Phases 6–7).
- Quantized weights and KV (FP8/NVFP4), speculative decoding, the Qwen and other model families, multimodal input (Phase 8 tracks; multimodal is out entirely). Image/audio parts in requests are rejected.
- Tool calling, `response_format`/structured output, `n` > 1, `logit_bias`, presence/frequency/repetition penalties (Phase 2 OpenAI compatibility).
- GPU-side sampling, HIP graphs, kernel autotuning, custom-kernel performance work — only after benchmarks show the need (TS §21 rule 3).
- Model download inside Turbine or its tests.

## Constraints

- Rust only in the build and runtime path of the workspace; the HIP shim is C++/HIP compiled by `hipcc` through CMake and exposes only a C ABI (TS §6). No Python in the serving path (TS §21 rule 4): Python appears only in `scripts/golden/hf_reference.py` (fixture generation) and, if Composable Kernel's instance generator requires it, inside the CMake build of _libturbine_hip.so_ — never in `cargo build` or `turbine-server`.
- The Rust workspace must build and every non-ignored test must pass on macOS arm64 with no GPU, no ROCm and no model weights (Phase 0 constraint, unchanged). Nothing links HIP at build time; _libturbine_hip.so_ (which itself links the ROCm runtime, hipBLASLt and CK) is loaded at run time.
- `unsafe` and FFI only in `turbine-device` and `turbine-kernels`, every block with a `// SAFETY:` comment. Ownership rules (TS §21 rule 10): every device pointer is allocated by the shim and owned by exactly one `DeviceBuffer`; the shim never retains a caller pointer beyond the call; streams and workspaces are owned by the shim context and destroyed with it; a `DeviceBuffer` must not outlive its context (enforced by holding an `Arc` of the context).
- New runtime dependencies: `safetensors` (header parsing), `tokenizers` (default features off, `onig` off, `fancy-regex` on), `minijinja` and `minijinja-contrib` (pycompat, for the Llama template), `smallvec`, `half` (bf16/f16 host conversion), `rand_chacha` (seeded sampling). Each is recorded in the crate manifest comment with its reason.
- External kernel libraries: hipBLASLt is taken from the ROCm 7.14.1 install at `/opt/rocm/rocm` (version logged at context creation); Composable Kernel is pinned by exact commit in `kernels/rocm/CMakeLists.txt`; licenses retained under `kernels/rocm/third_party/LICENSES/` (TS §6).
- Target hardware: novanas (192.168.10.203, Debian 13 amd64), one of its two AMD Radeon AI PRO R9700 (RDNA4, `gfx1201`, 32 GB dedicated VRAM each), ROCm 7.14.1 at `/opt/rocm/rocm` (off AMD's support matrix for Debian + RDNA4, so library coverage gaps are expected and are handled per S-7), k3s with `amdgpu-device-plugin`; runs are k3s Jobs (Phase 0). The user empties the R9700s for Turbine work.
- Any lab run that needs production workloads moved or memory freed on any host (novanas GPUs or the DGX Sparks' production vLLM) is preceded by asking the user; the user moves workloads. Turbine scripts never stop, restart or reconfigure other workloads.
- Weights: `meta-llama/Llama-3.2-3B-Instruct` in `/home/piwi/turbine-models/llama-3.2-3b-instruct` on novanas (and later on each host that runs it), downloaded once over SSH by Claude with a Hugging Face token the user supplies at that time; the token is never written to the repository, the scripts, the Job manifests or a file on the host. Tests and scripts never download.
- Bounded resources (TS §21 rule 8): one generation slot; the weight staging buffer is at most 256 MiB; safetensors headers larger than 100 MiB are rejected; request bodies keep the Phase 0 limit; the SSE channel to a client holds at most 64 events.

## Interfaces

### `turbine-server` startup (changes from Phase 0)

Order: parse and validate config (exit 2 on error) → discover devices → load the kernel provider for _execution.backend_ → parse model config and tokenizer → compute the memory budget → bind the listener (`/health` 200, `/ready` 503 `loading_model`) → load weights → one-token warm-up forward → `/ready` 200. Any failure after binding logs the cause, returns 503 `model_load_failed` on `/ready` for at most 1 s, and exits 1.

Exit codes: 0 clean shutdown; 2 invalid configuration or CLI usage; 1 any other startup failure (model files, unsupported architecture, kernel library, ABI or GPU-architecture mismatch, memory budget, weight load, warm-up).

| -------------------------- | ------------ | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |

| _model.dtype_              | enum         | `bf16`                                                     | activation, weight and KV dtype; only `bf16`                                                                                                       |
| _model.served_name_        | string       | derived (see below)                                        | non-empty, ≤ 256 chars                                                                                                                             |

| _model.chat_template_      | path or null | null → _chat_template.jinja_, else _tokenizer_config.json_ | must parse as a template at startup                                                                                                                |
| _model.max_seq_len_        | integer/null | null → min(32768, the model's _max_position_embeddings_)   | 1 ≤ value ≤ the model's _max_position_embeddings_                                                                                                  |

| _execution.device_         | integer      | `0`                                                        | a global index from the Phase 0 inventory; must be an AMD device when the backend is `hip`                                                         |

_model.served_name_ default: for a Hugging Face cache snapshot (`…/models--<org>--<name>/snapshots/<rev>`) it is `<org>/<name>`; otherwise the last path component of _model.path_. Lab configs set it explicitly to `meta-llama/Llama-3.2-3B-Instruct`.

### Kernel shim C ABI (`kernels/include/turbine_kernels.h`)

Vendor-neutral: no HIP or CUDA type appears in the header; _libturbine_hip.so_ implements it now and _libturbine_cuda.so_ implements the same header in `phase-2b-nvidia`.

- `uint32_t turbine_abi_version(void)` — must equal the Rust side's `TURBINE_KERNELS_ABI_VERSION` (starts at 1); a mismatch is fatal with both numbers in the message.
- `const char *turbine_backend_name(void)` (`"hip"`) and `const char *turbine_build_archs(void)` (comma-separated, e.g. `"gfx1201"`); the Rust side refuses a context when the device's `arch` from the Phase 0 inventory is not in the list.
- `int32_t turbine_ctx_create(int32_t device_ordinal, turbine_ctx **out)` / `void turbine_ctx_destroy(turbine_ctx *)` — the ordinal is the vendor-local index (`vendor_index` from the Phase 0 inventory).
- `int32_t turbine_malloc(turbine_ctx *, size_t bytes, void **out)`, `turbine_free`, `turbine_memcpy_h2d`, `turbine_memcpy_d2h`, `turbine_stream_sync`, `turbine_mem_info(turbine_ctx *, size_t *free, size_t *total)`.
- One `int32_t turbine_<op>(turbine_ctx *, const turbine_<op>_desc *)` per op (`gemm`, `attention_prefill`, `attention_decode`, `rmsnorm`, `rope`, `silu_mul`, `embedding`, `add`), each descriptor a plain C struct of device pointers, shapes, strides and dtype codes, plus `int32_t turbine_<op>_supported(const turbine_<op>_desc *)` backing `supports()`, and `const char *turbine_<op>_impl(const turbine_<op>_desc *)` naming the implementation chosen (e.g. `"hipblaslt"`, `"ck_tile_fmha_fwd"`, `"turbine_hip"`) for the selection log.
- Every call returns 0 on success or a negative code; `size_t turbine_last_error(turbine_ctx *, char *buf, size_t len)` returns the message. Codes: `-1` invalid argument, `-2` unsupported configuration, `-3` out of memory, `-4` device runtime error, `-5` library error.

### `kernels/rocm/` build

- `cmake -S kernels/rocm -B <build> -DCMAKE_HIP_COMPILER=/opt/rocm/rocm/bin/hipcc -DGPU_TARGETS=gfx1201 && cmake --build <build>` produces _libturbine_hip.so_; `TURBINE_ROCM_PATH` overrides `/opt/rocm/rocm`. ### HTTP routes (Phase 1 behaviour)

| Route                                           | Phase 1 response                                                                                                                               |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /ready`                                    | `503` `{"ready":false,"reason":"loading_model"}` while loading; `200` `{"ready":true}` after warm-up                                           |
| `GET /v1/models`                                | `200` `{"object":"list","data":[{"id":"<served_name>","object":"model","created":<unix>,"owned_by":"turbine","max_model_len":<max_seq_len>}]}` |
| `POST /v1/completions`                          | OpenAI text completion, streaming or not (fields below)                                                                                        |
| `POST /v1/chat/completions`                     | OpenAI chat completion, streaming or not (fields below)                                                                                        |
| `GET /turbine/v1/status`                        | Phase 0 body plus `"model":{"served_name":..,"architecture":..,"weight_bytes":..,"load_seconds":..}`                                           |
| `GET /turbine/v1/kv`, `/pressure`, `/scheduler` | unchanged: `501`                                                                                                                               |

Supported request fields: `model` (must equal the served name, else `404` `model_not_found`), `prompt` (string, or array of token ids — completions), `messages` (roles `system`/`user`/`assistant`, content a string or an array of `{"type":"text"}` parts — chat), `max_tokens` / `max_completion_tokens` (default: remaining context), `temperature` (0–2, default 1.0 unless _generation_config.json_ sets one), `top_p` (0 < p ≤ 1), `top_k` (−1 or ≥ 1), `seed`, `stop` (string or ≤ 4 strings), `stream`, _stream_options.include_usage_, `logprobs` (completions: integer 0–20; chat: bool with `top_logprobs` 0–20), `echo` false only, `n` 1 only, `ignore_eos` and `return_tokens_as_token_ids` (vLLM extensions), `chat_template_kwargs` (object passed to the template, e.g. `date_string`). Other known OpenAI fields at a non-default value (`tools`, `tool_choice`, `response_format`, `n` > 1, `logit_bias`, penalties, image/audio parts) → `400` `invalid_request_error` / `unsupported_parameter` naming the field. Unknown fields are ignored.

Errors (OpenAI shape): prompt + `max_tokens` > _model.max_seq_len_ → `400` `context_length_exceeded`; a generation already running → `429` `engine_busy` with `retry-after: 1`; not ready → `503` `model_not_loaded`; kernel/device failure during generation → `500` `internal_error` (streaming: an `error` event, then `data: [DONE]`, then the stream closes — CONFLICT C-3).

Streaming: `content-type: text/event-stream`; chunks `data: {"id":"cmpl-…","object":"text_completion"|"chat.completion.chunk",…}`; the first chat chunk carries _delta.role_; `finish_reason` is `stop` (EOS or stop string) or `length`; a final usage chunk when `include_usage`; then `data: [DONE]`.

### `scripts/golden/hf_reference.py`

```
uv run scripts/golden/hf_reference.py --model-dir <dir> --prompts tests/golden/prompts.jsonl
                                      --out tests/golden/<model-slug>/reference.jsonl
                                      [--top-logprobs 20] [--device cpu|cuda]
```

- Loads the checkpoint with `torch_dtype=torch.bfloat16`, applies the same chat template and `chat_template_kwargs` as Turbine, generates greedily for each prompt's `max_tokens`, and records per generated position the chosen token and the top-20 log-softmax values of the BF16 logits upcast to FP32. `engine` is `transformers-<version>-bf16-<device>`. Writes to a temp file and renames; exit 1 on any failure.
- Run by the implementer on any host holding the weights (CPU is sufficient for 3B); the resulting files are committed.

### `turbine-golden`

```
turbine-golden compare --url <base> --reference <reference.jsonl> [--model <name>]
                       [--tolerance <tolerance.json>] [--output text|json]
turbine-golden capture --url <base> --prompts <prompts.jsonl> --out <reference.jsonl>
                       [--model <name>] [--top-logprobs 20]
```

- `compare` replays each reference prompt against `--url` (`/v1/completions` for `completion` prompts, `/v1/chat/completions` for `chat` prompts) with `temperature: 0`, top-20 logprobs, `return_tokens_as_token_ids: true`, non-streaming, and reports per prompt: identical-prefix length of greedy tokens, first divergence position, the reference top-1/top-2 margin there, and max |Δ logprob| over the reference top-5 at each position before divergence. `--tolerance` defaults to _tolerance.json_ beside the reference. Exit 0 when the tolerance holds, 1 when it is violated, 2 on usage or I/O errors.
- `capture` writes the same record format from any OpenAI-compatible endpoint (engine identity from `system_fingerprint`), for recording other engines alongside the committed HF reference.

### Metrics (added)

- `turbine_model_load_seconds` gauge; `turbine_model_weight_bytes{format}` gauge (`format` ∈ `bf16` in Phase 1).
- `turbine_kernel_provider_selected{op,provider,impl}` gauge, 1 per chosen triple (`impl` from `turbine_<op>_impl`).
- `turbine_requests_total{endpoint,outcome}` counter — `outcome` ∈ `ok`, `cancelled`, `rejected`, `failed`.
- `turbine_request_ttft_seconds`, `turbine_request_itl_seconds`, `turbine_request_e2e_seconds` histograms.
- `turbine_tokens_total{kind}` counter — `kind` ∈ `prompt`, `generated`.
- `turbine_forward_seconds{phase}` histogram — `phase` ∈ `prefill`, `decode`.

## Data

- Nothing is persisted by `turbine-server`. Weights live in device memory for the process lifetime; the tokenizer and template in host memory.
- Model directory (read-only input, trust boundary per TS §16): `config.json`, `generation_config.json`, `tokenizer.json`, `tokenizer_config.json`, optional `chat_template.jinja`, and `model.safetensors` or `model.safetensors.index.json` + shards (Llama-3.2-3B-Instruct: two shards, ≈ 6.4 GB). Symlinks are followed, but only to regular files.
- Contiguous KV for Llama-3.2-3B: 28 layers × 2 × 8 KV heads × 128 × 2 bytes = 114,688 bytes per token; 3.76 GB at the default _model.max_seq_len_ of 32768.
- Golden fixtures, committed: `tests/golden/prompts.jsonl` — one `{"id":"p01","kind":"completion"|"chat","prompt":"…"|"messages":[…],"max_tokens":32,"chat_template_kwargs":{"date_string":"26 Jul 2024"}}` per line (a fixed `date_string` keeps the Llama template deterministic), 16 prompts covering English prose, code, CJK, emoji (multi-byte token boundaries), a ~2,000-token prompt, and chat with and without a system message. `tests/golden/llama-3.2-3b-instruct/reference.jsonl` — one `{"id":"p01","engine":"transformers-<ver>-bf16-<device>","model":"meta-llama/Llama-3.2-3B-Instruct","captured":"<RFC 3339>","prompt_token_ids":[…],"tokens":[<id>…],"top_logprobs":[[[<id>,<logprob>]…]…]}` per prompt. `tests/golden/llama-3.2-3b-instruct/tolerance.json` — `{"min_identical_prefix":32,"min_prompts_passing":14,"top_k":5,"max_abs_logprob_diff":0.15,"margin_nats":0.5}`: a prompt passes when its first 32 greedy tokens are identical to the reference, or when it diverges only at a position whose reference top-1/top-2 margin is below 0.5 nats; |Δ logprob| over the reference top-5 must stay ≤ 0.15 nats at every position before divergence on every prompt; at least 14 of 16 prompts must pass.
- Tiny synthetic checkpoint: generated into a temp directory per test run from a fixed seed; never committed.

## Edge cases

- Tied embeddings: no `lm_head.weight` in the checkpoint (Llama-3.2-3B); an untied checkpoint provides it; a tied checkpoint that also ships `lm_head.weight` uses the embedding and logs the ignored tensor.
- Llama-3 rope scaling: frequencies below/above the low/high thresholds and the smoothed band in between must match the transformers formula exactly (computed on the host in FP64, stored FP32).
- Safetensors header claims a range beyond the file, overlapping ranges, a shape whose byte size disagrees with the range, an unknown dtype, a header over 100 MiB, a shard listed in the index but missing, a tensor listed twice, a required tensor missing, a non-BF16 tensor.
- Prompt that tokenizes to 0 tokens; prompt exactly _model.max_seq_len_; `max_tokens: 0`; `max_tokens` omitted.
- Emoji/CJK tokens split across multiple byte-level tokens: streaming must hold bytes until a valid UTF-8 boundary; a stop string spanning two tokens; a stop string that is a prefix of generated text never completed.
- EOS id list with several ids (Llama-3.2: `128001`, `128008`, `128009` from _generation_config.json_ `eos_token_id` as a list); `ignore_eos: true`.
- `temperature: 0` with `top_p`/`top_k` set (greedy wins); `seed` given → identical output for identical request.
- Chat template: no system message (the template injects its own with the date), `date_string` absent (template calls `strftime_now`), assistant prefill as the last message, `add_generation_prompt`, a template `raise_exception` for an unsupported role → 400.
- Client disconnects mid-stream; client disconnects before the first token; second request arriving during prefill.
- Kernel library built for another architecture (not `gfx1201`) or ROCm libraries missing from the loader path: refused at context creation with the arch list or the missing library named.
- CK has no `gfx1201` instance for a required attention or RMSNorm configuration: `turbine_<op>_supported` reports it and the op is served by the minimal Turbine HIP kernel, visible in `turbine_kernel_provider_selected{impl="turbine_hip"}`.
- The device plugin exposes only the allocated R9700 inside the Job, so the inventory holds one AMD device at index 0 even though novanas has two.

## Failure modes

- **Model directory or file missing/unreadable:** exit 1 naming the path.
- **Unsupported architecture, dtype or weight format:** exit 1 naming the field and value and listing the supported set; nothing is loaded.
- **Malformed safetensors or missing tensor:** exit 1 naming the file, tensor and violated rule; no partial model is served.
- **Kernel library absent, unloadable, wrong ABI version or wrong GPU architecture:** exit 1 naming the path/versions/arch; the default search order is logged.
- **No provider supports an op for this model:** exit 1 naming op and config (e.g. `attention_prefill head_dim=128 kv_heads=8 dtype=bf16`).
- **Memory budget exceeded:** exit 1 before reading weights, logging weights, KV reservation, workspace, emergency reserve and available bytes.
- **HIP error or OOM during a request:** the request fails with 500 (or a stream `error` event followed by `data: [DONE]`, CONFLICT C-3), buffers are freed, the error is logged with request id and op; after 3 consecutive failed requests `/ready` returns 503 `device_error` and the server exits 1 (a restart is safer than a wedged context; recovery logic is Phase 3).
- **Tokenizer or chat template fails on a request:** 400 `invalid_request_error` with the template error; the engine is untouched.
- **R9700 occupied by another workload:** the Job stays pending or the budget check fails with the available bytes; the implementer asks the user to free the GPU and never evicts the other workload.
- **Reference endpoint unreachable during `turbine-golden capture`, or `hf_reference.py` fails:** exit 1; no partial fixture file is left behind (written to a temp file and renamed).
