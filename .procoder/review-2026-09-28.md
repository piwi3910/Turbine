## Phase 3 (reliability)

1. **SURVIVAL liveness fix** — `decisions.md:461-469`
   Q: when the pool enters SURVIVAL, do admitted-but-unstarted requests get requeued (A) or do in-flight prefills keep going (B)?
   Options: A) requeue unstarted, drop reservation; B) let in-flight prefills continue.
   Provisional pick: **A** (`reliability.recovery.survival_liveness: requeue_unstarted`, default; `continue_prefills` is the switchable alternative).

2. **KV headroom in admission (seed 1 recovery)** — `decisions.md:470-479`
   Q: how does admission stop re-escalating YELLOW → RED right after a SURVIVAL episode?
   Options: A) KV headroom gate on admission/refill; B) slow YELLOW's batch growth; C) relax the 60 s recovery criterion.
   Provisional pick: **A**.

3. **`device_memory` counts idle pre-allocated pools as free** — `decisions.md:480-489`
   Q: should the pressure signal `device_memory` treat an idle, empty KV pool and reserve as free?
   Options: A) subtract idle pre-allocated bytes from used; B) cap `kv.gpu.max_bytes` in the soak config only; C) measure only non-pool memory against its own budget.
   Provisional pick: **A**.

4. **Soak stall — drift per iteration, idle floor** — `decisions.md:490-504`
   Q: how to stop `step_time_drift` reading a shrinking batch as device degradation, and stop an idle engine sitting behind a full queue?
   Options: A) drift = pure decode p95 + idle-floor admission; B) A plus a frozen admitted target in ORANGE/RED; C) drop `queue_fill` as a signal.
   Provisional pick: **A**.

5. **Soak config `max_batch_tokens`** — `decisions.md:506-514`
   Q: should the soak config use the Phase 2c value (2,048) instead of 8,192?
   Options: A) use 2,048; B) keep 8,192, relax the ITL criterion; C) shrink the prefill budget under pressure.
   Provisional pick: **A**.
   Follow-up open question (same entry, `decisions.md:514-518`): how should `latency_drift` avoid false-triggering the circuit near the end of an overload run? Option 1 (work-cost model) was tried and **reverted** (`bf8afed`); provisional pick is **option 2** — drift feeds the circuit breaker only while pressure is GREEN.

6. **Per-shape drift baselines (OLMoE landing regression)** — `decisions.md:520-528`
   Q: how should `step_time_drift` avoid reading a full MoE batch as drift?
   Options: A) one calm baseline per shape bucket (rows × context, no cross-bucket extrapolation); B) a work-cost model (tried, reverted above); C) divide by batch size again.
   Provisional pick: **A**.

## Phase 4 (KV tiers)

7. **Eviction policy as a registered extension point** — `decisions.md:554-561`
   Q: should `kv.policy` become a pluggable `EvictionPolicy` registry (per the 2026-09-26 pluggability rule) rather than the closed enum the Phase 4 plan was written with?
   Options: A) trait + static registry (`cost_aware.rs`, `lru.rs`), conformance suite, `docs/extending/eviction-policy.md`; B) keep the closed enum, add the registry later.
   Provisional pick: **A**.

8. **Kernel ABI v2.5 instead of v3** — `decisions.md:563-570`
   Q: does Phase 4's pinned-memory/copy-stream/event surface need the planned major bump to ABI v3, or can it ship as an optional minor group?
   Options: A) optional minor group v2.5 (same names/signatures as the planned v3, only required once minor ≥ 5); B) the planned v3 (every function required, a v2 library refused).
   Provisional pick: **A**.

9. **Prefix attach before the admission gate** — `decisions.md:572-579`
   Q: does a request's cached-prefix attach happen before or after Phase 3's admission gate?
   Options: A) attach before the gate (reservation excludes attached blocks, held-pending-answer while a prefix is still promoting); B) attach after admission (reservation covers the whole prompt, no hold, but under-uses the pool).
   Provisional pick: **A**. Known limit noted in the same entry: blocks attached by requests still queued are referenced without their own reservation.

10. **L0 capacity demotion** — `decisions.md:581-589`
    Q: how does the orchestrator keep L0 headroom when a pool full of cached (unreferenced) prefix blocks never triggers the pressure controller's reclaim?
    Options: A) demote lowest-valued cached blocks by capacity above 0.70 utilization, before each plan; B) count cached blocks in `kv_utilization`; C) demote synchronously inside allocation.
    Provisional pick: **A**. This pick caused an 8% Llama throughput regression at the Phase 4 tip (see item 11), fixed by a follow-up provisional decision — the underlying design choice (A) is still pending user review.

11. **Capacity demotion only for blocks with reuse evidence** — `decisions.md:593-602`
    Q: how to fix decision 10's regression (1,214 unnecessary L0→L1 copies for one-off prompts)?
    Options: A) gate capacity demotion on reuse evidence (hit once, session, or ≥2 cached children), rate-limited to ≤32 blocks / 50 ms; A′) the same gate on pressure reclaim too (tried, rejected — breaks `kv-sim mixed`'s 0.9× LRU bound); B) a `kv.demote_min_value` threshold (no single value separates the cases); C) change the cost-aware reuse term (breaks other policy tests).
    Provisional pick: **A** (landed as `ba5ca6c`, in the merged Phase 4 candidate `1c4f92e`).

    Q: which small-m MoE tier design keeps decode output independent of batch composition?
    Options: A) small-m tier runs the grouped WMMA kernels on 16-row tiles (bitwise equal row-by-row with the large tier); B) drop the small-m tier entirely (4× wasted work); C) scalar small-m for every batch (slow prefill).

13. **OLMoE c16 flip fix: recovering the decode speed** — `decisions.md:639-647`
    Q: how to recover the −14.1% throughput regression option A (item 12) introduced?
    Options: A) tune dedicated small-tier WMMA decode kernels (one wave per 16 columns, 8 k-slices); B) split by row kind (decode vs prefill) into two launches per mixed layer; C) accept the regression.
    Chosen: **A** — "provisional (agent decision, pending user review)"; landed as `e22c375`. B is noted as the fallback if the served bench had missed the −3% bound (it did not).

19. **Phase 4: pressure reclaim copies only blocks with reuse evidence, ≤ 32 copies in flight** — `decisions.md` (same title)
