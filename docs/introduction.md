# Introduction

Turbine is an LLM inference engine written in Rust. It serves models over an OpenAI-compatible HTTP API, with server-sent event streaming, tool calls, reasoning content and JSON-schema structured output. The serving path contains no Python and no PyTorch: requests go from HTTP through Turbine's scheduler and KV cache to a GPU kernel library that Turbine loads at run time.

## Current state

- The first production target is the AMD Radeon AI PRO R9700 (gfx1201) with ROCm and HIP. Most of the work, the measurements and the lab tests run on that card.
- NVIDIA support (a CUDA kernel shim, NVFP4 weights) is designed for but deferred. The `nvidia` vendor is refused at startup with a reason code.
- A CPU reference backend exists for tests and tiny checkpoints. It is experimental and is not a serving target.
- Model families served on the R9700 include Llama, OLMoE, Qwen3 (dense and MoE), Mistral, Mixtral and gpt-oss-20b. Qwen3.5 and Qwen3.6 hybrids are experimental. See the [feature matrix](features.md) for the exact status of each combination.

Turbine is under active development. The feature matrix is the authority on what is supported today, and the server reports the status of the configured combination at startup and on `/turbine/v1/status`.

## Terms used in these docs

- **L0, L1, L2**: the KV cache tiers. L0 is the paged block pool in GPU memory, L1 is pinned host memory, L2 is NVMe slab files. Recomputing a block is a virtual tier below L2.
- **KV format**: the byte layout of a KV block in a tier. `l0` (the exact format), `fp8_e4m3`, `tq4` and `tq2` are the formats; the last three are lossy.
- **Pressure state**: GREEN, YELLOW, ORANGE, RED or SURVIVAL, from the pressure controller that watches device memory and host signals.
- **Circuit state**: HEALTHY, DEGRADED, CIRCUIT_OPEN, DRAINING or PROBING, from the circuit breaker that reacts to device errors.
- **Support row**: one entry of the support matrix, keyed by vendor, device architecture, model architecture, weight format, KV format and speculation. Each row resolves to `supported`, `experimental` or `unsupported`.
- **Reason code**: a snake_case code (for example `kv_tq2_l0_refused`) carried by every refusal and failure that the server reports in a machine-readable way.
- **Golden compare**: the numerics check that replays fixed prompts and compares token logprobs with a reference generated by Hugging Face transformers.
